## definition

Inject CPython lifecycle management into the Chromium renderer process, ensuring proper `Py_Initialize()` execution, Global Interpreter Lock (GIL) management, and per-tab execution context isolation.

## design

**1. Lifecycle Initialization (`ouro_python_runtime.cc`)**
Chromium typically initializes V8 in `RenderProcessImpl::Create`. We must write a patch to initialize Python instead.
```cpp
void RenderProcessImpl::InitializePythonRuntime() {
    if (!Py_IsInitialized()) {
        Py_Initialize();
        PyEval_InitThreads(); // Ensure GIL is active for multi-threading
        
        // Setup base sys.path or injected modules
        PyRun_SimpleString("import sys; sys.path.append('/opt/ourobrowser/lib')");
    }
}
```

**2. Context Isolation (The Frame Dict)**
V8 uses `v8::Context` to ensure different iframes/tabs cannot access each other's global variables. In Python, we will replicate this by assigning a unique `PyDictObject*` (a namespace dict) to each Blink `LocalFrame`. Every script executed by that frame runs exclusively against its isolated dict.

**3. GIL Wrappers (`ouro_gil_scope.h`)**
Blink fires DOM events (like clicks) asynchronously across multiple threads. Every C++ function generated by PC Egress must wrap its execution in the GIL.
```cpp
class PyGILScope {
public:
    PyGILScope() { gstate = PyGILState_Ensure(); }
    ~PyGILScope() { PyGILState_Release(gstate); }
private:
    PyGILState_STATE gstate;
};
```

## settled rules
- **Thread Safety:** Every entry point from Blink into Python *must* acquire the GIL. The browser will segfault instantly if multiple Blink threads attempt to execute Python script tags concurrently without the lock.
- **Strict Isolation:** `window.A` in Tab 1 must absolutely not be accessible as `window.A` in Tab 2. The global `__main__` module must be bypassed in favor of explicit, per-frame `PyDict` namespaces.
